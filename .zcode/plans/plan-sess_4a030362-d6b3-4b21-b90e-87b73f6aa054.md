# แผนสร้าง Peg Solitaire Multiplayer (React + Supabase + Tailwind v4)

## ภาพรวม
สร้างเกม Peg Solitaire แบบ multiplayer real-time head-to-head ที่ host สร้างห้องแล้วแชร์ link+รหัสให้ผู้เล่นคนอื่น join มี level ไล่ง่าย→ยาก, scoreboard, hint (หักคะแนน), timer และตั้งค่าห้องได้

**Stack:**
- Frontend: React 19 + Vite 6 + Tailwind v4 + react-router-dom v6
- Backend/Realtime: Supabase (Database + Realtime channels + RLS)
- State: React Context + useReducer (หลีกเลี่ยง dependency เพิ่ม)
- Anonymous play (ไม่มี auth) เก็บ identity ผ่าน `localStorage` + ชื่อเล่นที่กรอกเอง

## โครงสร้างฐานข้อมูล Supabase

### Table: `rooms`
```sql
- id uuid pk
- code text unique (6-char, e.g. "A3K9P2")
- host_id text  (persistentId)
- board_shape text  ('triangle'|'english'|'diamond'|'deutsch')
- level int  (1=triangle, 2=english, 3=diamond, 4=deutsch)
- timer_seconds int default 180
- max_rounds int default 3
- hints_allowed bool default true
- hint_penalty int default 50
- status text  ('waiting'|'playing'|'finished')
- created_at timestamptz
```

### Table: `players`
```sql
- id uuid pk
- room_id uuid fk -> rooms
- persistent_id text  (จาก localStorage)
- nickname text
- score int default 0
- pegs_remaining int default 0  (อัปเดตตอนจบรอบ)
- is_host bool default false
- finished_rounds int default 0
- last_seen timestamptz
```

### Table: `round_results`
```sql
- id uuid pk
- room_id uuid fk -> rooms
- player_id uuid fk -> players
- round_number int
- score_delta int
- pegs_remaining int
- hints_used int
- time_used_seconds int
- finished_at timestamptz
```

**RLS Policies:**
- rooms, players, round_results: read/write ผ่าน anon key แต่กรองด้วย `room_id` ที่รู้จาก room code
- Insert players ต้องมี `persistent_id` ตรงกับ host หรือเป็นคนใหม่ (ใช้ `room_id` + check duplicate)

**Realtime:**
- Subscribe channel `room:<room_code>` สำหรับ updates ของ players, round_results, status

## Game Logic (`lib/pegLogic.js`)

**Board representation:** 2D array ขนาด NxN โดยช่องที่ "ใช้ได้" ระบุจาก mask ใน `boards.js`
- `0` = หลุมเปล่า
- `1` = มี peg
- `null` = หลุมที่ไม่มีในกระดาน (เช่นมุมกากบาท)

**Move rule:** เลือก peg ที่มี peg ติดกัน 1 ช่อง แล้วข้ามไปลงหลุมว่างฝั่งตรงข้าม → peg ที่อยู่ตรงกลางถูกลบ
- ทิศที่เลื่อนได้: บน/ล่าง/ซ้าย/ขวา (4 ทิศ) — Peg Solitaire classic

**ฟังก์ชันหลัก:**
- `createBoard(shape)` → initial state
- `getValidMoves(board)` → list ของ move ทั้งหมด
- `applyMove(board, move)` → board ใหม่
- `countPegs(board)`
- `isGameOver(board)`
- `findBestMove(board)` → สำหรับ hint ใช้ heuristic (move ที่ทำให้เหลือ peg น้อยที่สุด, tie-break ด้วย move ที่เปิดทางได้มากที่สุด)

## Scoring System (`lib/scoring.js`)

คะแนนต่อรอบ = `base_pegs_remaining * 100 - hints_used * hint_penalty - time_bonus`

- `base_pegs_remaining`: จำนวน peg ที่เหลือ × 100 (เป้าหมายคือ 1 peg = 100 คะแนน)
- `hints_used * hint_penalty`: hint_penalty ตั้งจาก host (default 50)
- `time_bonus = max(0, (timer_seconds - time_used) / 5)`: จบเร็วได้โบนัส
- ถ้าแพ้ (เหลือ > 1 peg): ไม่ได้คะแนน base แต่ยังได้ time_bonus - hint_penalty

**Hint penalty scaling** (คำนวณตามความเหมาะสม):
- hint แบบ "เฉลย move ที่ดีที่สุด" = penalty 50 คะแนน/ครั้ง
- hint แบบ "highlight ทุก move" = penalty 20 คะแนน/ครั้ง
- Host ตั้ง `hint_penalty` ได้ในช่วง 0–200 → ผู้เล่นต้องคำนวณคะแนนจากค่าที่ host ตั้ง

## Multiplayer Flow (Real-time Head-to-Head)

เนื่องจากเล่นคนละคน ไม่ใช่ turn-based แต่เป็น "แข่งคะแนนในเวลาเดียวกัน":

1. Host กด Start ใน Lobby → `status = 'playing'`, ทุกคนเริ่ม round พร้อมกัน (timer เริ่ม)
2. แต่ละคนเล่นบนกระดานของตัวเอง (state เก็บ local ในแต่ละ client) — game state ไม่ sync ผ่าน realtime เพราะแต่ละคนตัดสินใจเอง
3. จบเกม (เหลือ 1 peg หรือ stuck) → submit `round_result` ผ่าน Supabase
4. เมื่อทุกคน submit หรือ timer หมด → host กด Next Round (หรือ auto-end ตามที่ตั้ง)
5. หลังจบทุกรอบ → `status = 'finished'` → redirect ไปหน้าสรุปคะแนน

**Realtime subscribe** ใน GamePage:
- Listen changes ของ `players.score`, `players.pegs_remaining`, `players.finished_rounds`
- Listen `round_results` ใหม่เพื่ออัปเดต scoreboard

## ข้อควรระวัง
- **Supabase URL/Key:** ผู้ใช้ต้องสร้างโปรเจกต์ Supabase เอง (อาจแนะนำให้ทำตอน runtime หรือมี mock ให้ทดสอบก่อน)
- **RLS:** ถ้าตั้งผิด ผู้เล่นอาจเห็นข้อมูลห้องอื่นได้ — เขียน policy ให้รอบคอบ
- **Realtime payload:** Supabase Realtime ส่ง payload ทั้ง row — ออกแบบให้ trigger เฉพาะ field ที่จำเป็น
- **Concurrent updates:** ใช้ `score` column ที่อัปเดตด้วย increment (round results) ไม่ใช่ replace — ป้องกัน race condition
- **Disconnect handling:** ใช้ `last_seen` + filter players ที่ออกไปแล้วใน UI
